# wui

A **shadcn-style React component library you own** — components are copied into
your project on demand (not installed as a black-box dependency), documented on
a live Fumadocs site, and distributed through a shadcn-compatible registry that
a branded `wui` CLI (or the official `shadcn` CLI) can pull from.

## Monorepo layout

```
wui/
├─ apps/docs/            # Next.js + Fumadocs docs & demo site (also hosts the registry JSON)
│  ├─ registry/          # component SOURCE OF TRUTH (ui/, components/, lib/, examples/)
│  ├─ content/docs/      # MDX documentation (parsed to pages)
│  ├─ components/        # ComponentPreview / ComponentSource / CodeTabs / PropsTable
│  ├─ scripts/           # build-registry.mts, build-docgen.mts, build-llms.mts, new-component.mts
│  ├─ llms/overview.md   # authored: the rules an LLM must follow when writing wui code
│  ├─ app/api/mcp/       # Streamable HTTP MCP endpoint
│  ├─ public/r/          # GENERATED: distributable {name}.json (served to the CLI)
│  │  └─ llms/           # GENERATED: condensed digests (served to the MCP server)
│  └─ registry.json      # registry manifest
├─ packages/cli/          # the `wui` CLI (@wui-design/cli): init / add / build / list / view
├─ packages/mcp/          # the MCP server (@wui-design/mcp): shared core + stdio entry
├─ docs/COMPONENT-SPEC.md # 《组件新增规范》 — how to add a component
├─ docs/DESIGN-TOKENS.md  # component-library token contract and governance
└─ docs/MCP.md            # 《MCP 接入》 — exposing the library to AI coding tools
```

## Tech stack

React 19 · TypeScript · Tailwind CSS v4 (oklch, CSS-first) · Radix (`radix-ui`) ·
`class-variance-authority` · Next.js 15 (App Router) · Fumadocs · Shiki ·
pnpm workspaces + Turborepo.

## Develop

```bash
pnpm install
pnpm --filter docs registry:build   # generate public/r/*.json + preview indexes
pnpm --filter docs dev               # docs site at http://localhost:3000
```

Other gates: `pnpm typecheck`, `pnpm --filter docs tokens:audit`, `pnpm build`,
`pnpm --filter @wui-design/cli test`.

## Add a new component

```bash
pnpm --filter docs gen:component <name>     # scaffold source + demo + MDX + registry entry
# …implement it, fill in the docs…
pnpm --filter docs registry:build
```

See [`docs/COMPONENT-SPEC.md`](./docs/COMPONENT-SPEC.md) for the full spec (code
conventions, the 5 required doc sections, and the checklist).

## Pull components into a project

```bash
pnpm dlx @wui-design/cli@latest init       # writes wui.json + the cn() helper
pnpm dlx @wui-design/cli@latest add button # copies button (+ its registry deps) into your project
```

Because the registry follows the shadcn `registry-item.json` schema, the
official CLI works too:
`pnpm dlx shadcn@latest add https://ui.wzx.wang/r/button.json`.

> The CLI defaults `@wui` to `https://ui.wzx.wang/r/{name}.json`. Point it at
> another deployment (any host serving `public/r/`) with
> `wui init --registry https://your-site/r/{name}.json`.

## Use it from an AI coding tool (MCP)

Give Claude Code / Cursor / Windsurf the real props, usage rules, and examples
instead of letting them guess:

```bash
claude mcp add --transport http wui https://ui.wzx.wang/api/mcp   # remote, zero install
claude mcp add wui -- pnpm dlx @wui-design/mcp@latest             # or over stdio
```

The digests are generated by `registry:build` from the same sources the docs
site uses, so **a new component shows up in MCP with no extra work**. See
[`docs/MCP.md`](./docs/MCP.md).
