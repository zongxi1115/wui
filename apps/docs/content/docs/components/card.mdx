## 使用场景

`Card` 用于组合属于同一对象或任务的信息与操作，例如项目摘要、资源概览和设置入口。卡片应有独立的阅读意义，
用户单独看到它时也能理解内容主题。如果内容只是页面布局的一部分，优先使用普通容器和分隔线，不要把每个区块都包成卡片。

组件只负责表面、层级和间距，不内置点击行为。整张卡片需要可点击时，应在业务层使用语义正确的链接或按钮，
并保留清晰的焦点样式；一张卡片中有多个操作时，不要再把整张卡片包成另一个点击区域。

`Card`、`CardHeader`、`CardTitle`、`CardDescription`、`CardAction`、`CardContent` 与 `CardFooter` 均透传对应 `div` 的原生属性。

## 事件

卡片本身不产生业务事件，原生鼠标、键盘和焦点事件会继续透传。操作应放在 `CardAction` 或 `CardFooter` 内的 Button、
链接等交互元素上，避免在一张卡片中嵌套相互冲突的点击区域。

## 扩展用法

### 紧凑组合

<ComponentPreview name="card-composition" />

通过覆盖 `gap`、内边距和边框类，可以让卡片适应不同的信息密度。`CardAction` 适合标题旁的单个轻量操作；
一组主要和次要操作应放在 `CardFooter` 中，并按从主要到次要的顺序排列。
