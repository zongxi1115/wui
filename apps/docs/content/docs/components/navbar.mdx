## 使用场景

`Navbar` 用来承载应用的主要目的地、品牌入口和全局操作。横向布局适合页面顶部；当产品包含多个稳定模块，
并且用户需要在模块之间持续切换时，使用纵向布局作为左侧导航。组件只负责布局和交互，不负责路由，当前页面应由业务层
根据路由状态传入 `active`。

## 属性

<PropsTable name="navbar" />

- `Navbar` 通过 `orientation="horizontal | vertical"` 控制整体方向。
- 纵向模式支持 `collapsed`、`defaultCollapsed` 和 `onCollapsedChange`；`NavbarCollapseTrigger` 提供收起和展开按钮。
- `NavbarLink` 支持 `active` 和 `asChild`，可组合 Next.js `Link` 或其他路由链接。
- `NavbarHeader`、`NavbarContent`、`NavbarGroup` 和 `NavbarFooter` 用来划分品牌、导航、分组和底部操作区域。
- `NavbarLabel` 只在纵向布局显示，适合给一组导航补充分组名称。
- `NavbarSubmenu`、`NavbarSubmenuTrigger` 和 `NavbarSubmenuContent` 用于展示二级目的地。
- `NavbarSubList` 与 `NavbarSubLink` 负责排列浮层中的二级链接。

## 事件

导航事件由 `NavbarLink` 渲染的原生链接或 `asChild` 子元素处理。当前页面会自动获得 `aria-current="page"`；
路由跳转、埋点和权限判断应由业务层的链接或路由组件处理。键盘焦点沿用浏览器的链接与按钮顺序。

## 扩展用法

### 全局左侧导航

<ComponentPreview name="navbar-vertical" />

纵向布局适合后台、工作台和多模块工具。示例同时展示右侧浮入的二级导航和宽窄收起：指针悬停或键盘聚焦“项目”时，
子栏目从侧栏右侧出现；收起后保留图标入口，并通过 `title` 或 `aria-label` 说明目的地。

需要由页面布局保存收起状态时，传入 `collapsed` 和 `onCollapsedChange`；普通场景只放置 `NavbarCollapseTrigger` 即可使用内部状态。
导航分组不宜过多，同一层级优先保持少量可见入口，避免把所有功能都塞进导航栏。
