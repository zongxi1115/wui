## 使用场景

`AiChat` 用于搭建 Agent 助手、客服和 Copilot 对话界面。它处理消息布局、跟随滚动、回到底部和输入区组合，
不处理模型请求、消息协议或会话存储，因此既可以接 AI SDK，也可以接自有流式接口。

默认头像复用通用 [`Avatar`](/docs/components/avatar)，输入区可以复用 [`AiPrompt`](/docs/components/ai-prompt) 的基础部件。
需要提及、模型选择、附件或引用时，可以直接用完整的 `AiPrompt` 替换底部输入区。

如果界面只是普通评论列表或站内私信，应继续使用业务列表组件；不要因为内容由 AI 生成，就套用包含流式状态和回到底部能力的完整聊天外壳。

## 事件

`AiChatPrompt` 透传表单的 `onSubmit`，业务层负责读取输入、发送请求并控制 `AiChatSubmit` 的 `status`。
`AiChatTextarea` 透传原生输入和键盘事件；示例约定 Enter 发送、Shift + Enter 换行。消息操作区不预设复制、重试或反馈逻辑，
这些操作应由业务层根据消息状态决定。

## 扩展用法

### 与工具、任务和推理组合

聊天框保持为复合组件：在助手消息中放入 [`AiTool`](/docs/components/ai-tool)、[`AiTodo`](/docs/components/ai-todo) 和
[`AiReasoning`](/docs/components/ai-reasoning)，即可呈现 Agent 的工具调用、任务计划和过程摘要，不需要为每种消息类型增加新的固定模板。

### 流式消息

请求提交时将 `AiChatSubmit status="submitted"`，收到首段内容后切换为 `streaming`，生成结束或失败后恢复 `idle`。
`AiChatMessages` 只会在用户仍位于底部时跟随新内容；用户向上阅读历史记录后不会被强制拉回，应通过回到底部入口提示有新内容。

### 空状态

没有消息时，在 `AiChatMessages` 内使用 `AiChatEmptyState`，放置一句明确的能力说明和少量起始建议。
起始建议应能直接填入输入框或触发真实动作，避免堆叠宣传文案、装饰插画和过多快捷入口。
