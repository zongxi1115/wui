## 使用场景与设计规范

`Message` 用于对用户的轻量级操作提供**即时非阻塞反馈**（如“复制成功”、“草稿已保存”、“正在上传”等）。

- **非阻塞原则**：Message 通过 Portal 挂载在最顶层，不应抢占用户的交互焦点，也不应强制用户点击确认才能继续操作。
- **简短精炼**：提示文字应尽量控制在 20 个字符以内（1~2 秒即可阅读完）。若需展示多行报错信息、排查说明或复杂表单错误，请使用 `Alert` 或 `Dialog`。
- **避免多条轰炸**：若同一操作触发了多次异步回调，优先合并为单条更新，或依赖组件内置的 `stacked` 堆叠与 `maxCount` 机制避免屏幕被弹窗淹没。

## 无障碍与交互 Accessibility

- **动态实时区域 (Live Region)**：
  - `warning` 与 `destructive` 消息自动分配 `role="alert"`，协助读屏器及时播报错误。
  - 普通信息与成功提示使用 `role="status"`，确保在不打断用户当前焦点操作的前提下进行提示。
- **焦点与键盘交互**：当展开为列表并包含 `closable` 按钮或交互链接时，支持通过键盘进入并激活操作。
- **减弱动态效果 (Reduced Motion)**：组件会自动监听操作系统的减弱动态效果偏好（`prefers-reduced-motion`），开启时将禁用位移、缩放与毛玻璃模糊动效，以纯淡入淡出形式呈现。
