## 使用场景与设计规范

`ColorPicker` 专为**设计系统 Token 配置、主题定制与多媒体视觉编辑**场景设计：

- **为什么推荐 OKLCH 色彩空间**：传统的 sRGB/HSL 色彩模型在感知明度（Perceptual Lightness）上是非均匀的（例如纯黄色与纯蓝色在 HSL 中 Lightness 都是 50%，但人眼感觉黄色要刺眼得多）。OKLCH 实现了真正的“感知均匀”，无论色相如何改变，相同的明度（Lightness）在人眼中具有一致的视觉亮度，非常适合自动化生成符合 WCAG 对比度标准的暗色/亮色调色板。
- **模式双轨制**：
  - **基础 RGB 模式**：包含直观的 2D 饱和度-明度色盘与 R/G/B 分通道数字微调，适合大多数通用业务用户。
  - **专业 OKLCH 模式**：将明度（L）、色度（C）和色相（H）完全解耦独立控制，适合高级设计师与设计系统工程师。
- **色彩对比度与可访问性**：在业务中允许用户自定义主题色或文字背景色时，建议在表单提交前配合对比度算法（如 APCA 或 WCAG 2.1 4.5:1）做前置校验，防止用户配置出无法阅读的低对比度配色。

## 场景示例

### 受控模式与快捷预设

使用受控的 `value` 与 `onValueChange`，配合外部快速预设按钮直接改变颜色值：

<ComponentPreview name="color-picker-controlled" />

```tsx
const [color, setColor] = React.useState("oklch(0.585 0.233 277.117)")

return (
  <ColorPicker
    value={color}
    onValueChange={setColor}
  />
)
```

## 无障碍与交互 Accessibility

- **ARIA 规范**：
  - 触发器按钮带有清晰的 `aria-label`。
  - 2D 色盘声明为 `role="slider"`，并携带 `aria-valuemin="0"`、`aria-valuemax="100"`、`aria-valuenow` 与详细的 `aria-valuetext`（例如 `饱和度 85%，亮度 60%`）。
- **键盘导航**：
  - 聚焦在 2D 色盘上时，使用 <kbd>←</kbd> / <kbd>→</kbd> 微调饱和度，使用 <kbd>↑</kbd> / <kbd>↓</kbd> 微调亮度。
  - 按住 <kbd>Shift</kbd> + 方向键可进行大步长加速微调。
  - 聚焦在滑块（Range Input）上时，使用方向键与 <kbd>PageUp</kbd> / <kbd>PageDown</kbd> 调节数值。
- **高对比度外框**：触发器内置内发光与边框隔离环，即便选取的颜色与当前页面背景色相同（如纯白或纯黑），也能清晰呈现色块边界。
