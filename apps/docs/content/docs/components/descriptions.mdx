## 使用场景

`Descriptions` 用于只读呈现项目、订单、账户或设备等单个对象的属性。它适合“字段—值”的阅读方式；
需要比较多条同构记录时，应使用 Table，而不是重复堆叠多个描述列表。

## 属性

<PropsTable name="descriptions" />

每个 `DescriptionsItem` 都需要提供 `label`，值放在子内容中；通过 `span` 可以让一项跨越多个描述列。
标签应简短稳定，较长的帮助说明应放在值下方或字段外部，不要把整段解释写进标签。

## 事件

描述列表本身不产生业务事件。通过 `extra` 放置编辑、复制等轻量操作；字段值中的链接或按钮仍保留各自的原生事件。

## 扩展用法

`bordered` 适合信息密度较高的管理页面，默认分隔线样式更轻；`layout="vertical"` 适合标签较长或容器较窄的场景。
`columns` 与 `span` 应配合使用，每一行的跨列总数不要超过当前行容量，否则内容会换到下一行。
